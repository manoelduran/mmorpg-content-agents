# Eval Findings Fixes

## Overview

The first DeepEval run (`evals/`, judge `nvidia/nemotron-3.5-super-vl:free`)
failed 2 of 9 cases and flagged four problems. Checked against the code and
the manifests, two are real pipeline defects and two are blind spots in the
eval itself:

| Finding | Verdict | Root cause |
|---|---|---|
| Drops and shop items in English while lore/quests are pt-BR | **Real** | Only the Story prompt states the content language; `openrouter-dev-agent.ts` and `generate-shop-inventory.skill.ts` never mention one. |
| `TALK_TO_NPC` quests don't teach lore | **Real** | The schema has nowhere to put the fact being taught. `narrative`/`objectiveSketch` only *point at* a topic ("aprenda sobre os rituais…"); what the target NPC actually says exists nowhere in the manifest. |
| `giverNpcId` doesn't match the NPC named in the narrative | **False positive** | The narrative names the *target* NPC (`dev.questObjectives[].objectiveTarget`), not the giver. The judge never saw the target. |
| Zafira/Rami referenced but not in the NPC roster | **False positive** | They're `bossCompletion.questGiverName` instance companions, outside the 8-NPC roster by design (`city-template.value-object.ts`). |

This feature fixes the two real defects in the pipeline and the two blind
spots in the eval, then validates the result on a freshly generated city.

### Data Model: `CityQuestSchema`

New field:

| Field | Type | Rule |
|---|---|---|
| `loreReveal` | `string`, optional in the zod shape | **Required and non-empty** when `objectiveType === "TALK_TO_NPC"`; **must be absent** when `objectiveType === "KILL_MONSTER"`. Enforced with `.superRefine()` on `CityQuestSchema`, with an issue message naming the quest id. |

`.describe()` text for the field, which is also what the model sees through
the JSON Schema: *"TALK_TO_NPC only: what the target NPC actually tells the
player, written as that NPC's in-character speech, 2–4 sentences. It must
state at least one concrete fact (a name, place, event, or cause), may
introduce facts beyond the city's lore paragraph as long as it doesn't
contradict it, and must not repeat a fact another quest's loreReveal already
teaches."*

Why it's optional in the shape plus a refinement, not a discriminated union:
it keeps `CityQuest` a single flat type for every consumer
(`checkReferentialIntegrity`, guardrails, the eval), and the JSON Schema
stays simple enough for free models' structured-output support.

### Business Rules

1. **One language source.** `content-language.ts` exports one instruction
   string (pt-BR, every player-facing string: names, lore, dialogue, quest
   text, item names and item descriptions; ids stay kebab-case ASCII).
   Story, Dev, and `GenerateShopInventorySkill` interpolate that same
   constant into their system prompts. No prompt restates the language rule
   in its own words. This mirrors the `city-template.value-object.ts` rule
   for counts: one source, prose copies only by interpolation.
2. **Story prompt, `TALK_TO_NPC` bullet.** Replace "objectiveSketch names
   which npc to talk to and what piece of lore…" with: objectiveSketch names
   the target npc; loreReveal holds what that npc actually says. Allow
   expansion beyond the lore paragraph, forbid contradiction and repetition
   across quests. The bullet stays mechanical; the field's `.describe()`
   carries the detail, so the two can't drift.
3. **No deterministic language check in TS.** A stopword heuristic would
   false-positive on fantasy names and burn quota on retries. The eval's
   `:language` metric is the quality gate (decision from the spec
   interview).
4. **Guardrails cover the new field.** `loreReveal` is model-written,
   player-facing text, so it goes through the same
   `INJECTION_ECHO_PATTERNS` scan as `narrative`.
5. **No migration of existing manifests.** `output/aethelgard` and
   `output/necropolis-de-eter` stay as they are (decision from the spec
   interview). See Error Handling for what that breaks.

### Case and Metric Changes

- **`:talk-quests` case.** `actual_output` becomes, per `TALK_TO_NPC` quest:
  `title`, `giverNpcId` + giver name, `objectiveTarget` + target name
  (joined from `dev.questObjectives` and `story.npcs`), `narrative`, and
  `loreReveal` when present.
- **"Quests TALK_TO_NPC ensinam lore" steps.**
  - Judge the fact in `loreReveal`. A quest with no `loreReveal` (old
    manifests) scores as teaching nothing.
  - State that the giver and the target are different NPCs by design, so a
    narrative naming the target is correct.
  - Allow facts beyond the input lore, and penalize only contradictions and
    repeats.
- **"Coerência narrativa" steps.** Add one step saying that
  `bossCompletion.questGiverName`, `outboundGuardian` and `returnGuide` are
  companion NPCs outside the 8-NPC roster by design, and must not be
  penalized for missing from `npcs`.

## Testing Strategy

Pipeline (`npm test`, `node --test` via tsx, no mocking framework, per
AGENTS.md):
- `city-template.value-object.test.ts`: plain-object unit tests of the
  `loreReveal` refinement.
- `apply-content-guardrails.use-case.test.ts`: an injection echo placed in
  `loreReveal` is reported.
- `openrouter-story-agent.test.ts`, `openrouter-dev-agent.test.ts`,
  `generate-shop-inventory.skill.test.ts`: each uses the existing
  `FakeChatCompletionClient` pattern and asserts that the captured
  `systemPrompt` contains `CONTENT_LANGUAGE_INSTRUCTION` (plus, for Story,
  the `loreReveal` wording).
- Existing suites stay green after `valid-city.fixture.ts` is updated.
- `npm run typecheck`, `npm run build:schema` (the regenerated schema shows
  `loreReveal`).

Evals (no automated tests; the eval itself is the check):
- Re-run `npm run eval` on the existing two manifests. The failure reasons
  must no longer cite the giver/narrative mismatch (Aethelgard) or
  Zafira/Rami (Necrópolis). Their `:talk-quests` scores are expected to drop
  or stay failing, since they have no `loreReveal`.
- Generate one new city with free models, add it to `goldens.json`, and run
  `npm run eval -- <cityId>`.

## Error Handling

| Scenario | Behavior |
|---|---|
| Model omits `loreReveal` on a `TALK_TO_NPC` quest, or adds one to a `KILL_MONSTER` | zod refinement fails, so `StructuredOutputValidationError` feeds the issue back through the existing self-correction retry (`run-structured-openrouter-agent.ts`). After the retry budget it fails the run before Art/Dev are dispatched, so no extra cost is spent. |
| `loreReveal` echoes an injected instruction | `ContentGuardrailViolationError` before the story checkpoint is saved, same as `narrative` today. |
| `npm run regenerate:shop` on a pre-change manifest (`output/aethelgard`, `output/necropolis-de-eter`) | `ContentPackageSchema.parse` now rejects it (missing `loreReveal`). This is accepted: existing manifests are not migrated. The zod error names the quest ids, so the cause is readable. |
| Resuming a run whose checkpoint was saved before this change at phase `story` or `assets_and_dev` | `AssemblePackageUseCase`'s `ContentPackageSchema.parse` rejects the old story. Start a new `--run-id` instead. Note this in the commit message. |
| Free judge model rotates out of OpenRouter's free tier | `evals/judge.py` already refuses non-`:free` ids. Pick a replacement from `list_free_judges.py`. Not something this feature changes. |

## Assumptions

- **Output location.** The `spec-writer` skill targets
  `mmorpg-backend/docs/`. This feature lives entirely in
  `mmorpg-content-agents`, a separate repo with no backend/frontend surface,
  so the docs live in this repo's `docs/features/` instead.
- **Process.** No PRD exists for this feature (standalone mode). The
  "backend/frontend" split from the skill template doesn't apply; the two
  sides here are the TS pipeline and the Python evals.
- **Free models only, for generation and judging.** A validation city costs
  about 28 generation requests plus about 5 judge requests, well inside the
  1000/day quota.
- **Installer.** The future installer in `mmorpg-backend` will want to
  consume `loreReveal` as the target NPC's dialogue. That installer is out
  of scope here (README, "Manifests, not code").
